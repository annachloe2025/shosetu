# 主人公魔法

## このカテゴリについて

主人公の固有魔法の核心は「**魔法でコンピュータを再現する**」ことである。

現代地球の記憶を持って転生した主人公だけが、
この世界の魔力・術式の仕組みを「情報処理」の概念で捉え直すことができる。

> **重要：** この魔法体系は**構築に時間がかかる段階的な技術**である。
> 最初から全部使えるわけではなく、部品を一つずつ開発・組み合わせることで
> 最終的に「魔法のコンピュータ」が完成する。
> 物語の中での成長・発明の過程そのものがドラマになる。

## 部品①：念写魔法（ねんしゃまほう）
**── カメラ・スキャナーに相当 ──**

### 概要

「見ているものを、石板や紙にそのまま書き写す」魔法。
現代でいうカメラのシャッターを切る動作に近い。

### 世界の魔法との接続

感知系魔法はすでに「魔力の流れを読む・生物の位置を捉える」能力を持つ。
これを拡張すると、「視覚情報を魔力パターンとして捉える」ことが理論上可能になる。

```
感知系魔法（既存）：魔力の流れを「読む」
　　　↓ 拡張
念写魔法：視覚情報を魔力パターンとして「捉え」→「書き出す」
```

感知系の熟練使いは、術式石に「見た映像を特定の媒体に転写する」術式を転写することで
念写機能を実現できると考えられる。
ただし**この組み合わせを発想した者がいなかった**だけで、理論的には既存技術の延長線上にある。

### 主人公がどう習得するか（案）
- 感知系使いと同調し、「視覚を魔力として読む」感覚を体感する
- そこに「術式の仕組み」の知識を組み合わせて、「記録して書き出す」という応用を発明する
- 最初は精度が低く白黒のおぼろげな像しか転写できず、練習で鮮明になる

### 現在の状態
- 🔲 習得方法の詳細（物語上のエピソード）を決める
- 🔲 転写の精度・制限（色・動体・距離など）を詰める
- 🔲 消費魔力の設定

## 部品②：魔石記憶（まぎしきおく）
**── ストレージ・メモリに相当 ──**

### 概要

念写魔法で捉えた映像を**魔石に保存**し、念視魔法で任意のタイミングで読み出せる機能。
書き込みは「念写の応用」、読み出しは「念視の応用」で行う。

術式石（既存）が「魔術パターンの記録・再生」であるのに対し、
魔石記憶は「視覚情報パターンの記録・再生」への応用である。

> 詳細設定は [[魔石記憶]] を参照

### 現在の状態
- ✅ 基本原理（術式石応用・念写書き込み・念視読み出し）を確定
- ✅ 静止画と動画の違い・動画には連続書き込みが必要なことを確定
- 🔲 魔石の等級と保存容量の関係を詳細設定する

## 部品③：念視魔法（ねんしまほう）
**── 監視カメラ・ウェブカメラに相当 ──**

### 概要

遠隔地に設置した**目型魔石**から、リアルタイムで視界情報を取得する魔法。
念写の「脳→魔紙」とは逆方向の「魔石→脳」という情報の流れで成立する。

目型魔石は球体に加工した魔石に、光の入口以外をコーティングした構造を持ち、
光が「網膜相当の収束点」に集まる。術者はその情報を同調魔法で脳に受信する。

> 詳細設定は [[念視魔法]] を参照（修行部屋・訓練法・目型魔石構造を含む）

### 現在の状態
- ✅ 基本原理（念写の逆・目型魔石の構造・修行法）を確定
- ✅ 遠隔接続の仕組み（微量魔力→接続→映像受信）を確定
- ✅ 同調魔法士限定である理由を確定
- 🔲 リアルタイム送信の魔力消費量を詳細設定する
- 🔲 盗聴・傍受のリスクを設定する

## 部品④：魔石ネットワーク（まぎしねっとわーく）
**── インターネット・通信インフラに相当 ──**

### 概要

各所に魔石を配置し、念話の要領で少量の魔力を流すことで遠隔から魔石を操作・接続できるようにする。
これが他の部品を繋ぐ「通信インフラ」になる。

### 世界の魔法との接続

念話（同調魔法）：同調により魔力の振動で情報を伝達できる（既存）。
これを「人対人」から「人対魔石」「魔石対魔石」に拡張する。

```
念話（既存）：術者A ⇄ 術者B
　　↓ 応用
魔石ネットワーク：術者 → 魔石A → 魔石B → 魔石C（中継）→ 魔石サーバー
```

### ネットワークの基本設計（草案）

- 各地点に「中継魔石」を設置する
- 中継魔石は受け取った魔力信号を次の魔石へ転送する術式が込められている
- 主人公は同調魔法でネットワーク全体を「感じる」ことができ、
  どの魔石にアクセスするかを意識して操作する

### 現在の状態
- 🔲 中継距離・中継魔石の必要数を設定する
- 🔲 ネットワークの障害（魔石が壊れた場合の代替経路）を設定する
- 🔲 他の人間が同じネットワークを使えるかどうかを決める

## 部品⑤：魔法プログラミング
**── ソフトウェア・プログラムに相当 ──**

### 概要

術式石に魔術を転写する際に、**ループ（繰り返し）・分岐（条件による処理の切り替え）**
という概念を組み込む。

これが現代知識なしでは絶対に不可能な、主人公だけの独創的な発明である。

### なぜこの世界の人にはできないか

この世界の術式師は「一つの魔術パターンを転写する」という発想しか持っていない。
術式は「呪文の録音」であり、「計算機」ではないという認識。

主人公は「術式＝命令の列」として捉え、条件分岐とループという**制御構造**を
魔力パターンに組み込む方法を開発する。

### 具体的なイメージ（草案）

```
【従来の術式】
　「火を出せ」という1命令を転写 → 起動すると火が出る（固定）

【魔法プログラミング】
　「もし魔力Aが流れたら火を出せ、もし魔力Bが流れたら水を出せ」
　「魔力が供給される間、ループして映像を更新し続けろ」
　→ 入力によって動作が変わる・繰り返す動作ができる
```

### 主人公だけが発明できる理由

- ループ・分岐という概念がこの世界に存在しない
- 「魔術を命令として列挙する」という設計思想がない
- 現代のプログラミング知識があって初めて、術式を「コード」として設計できる

### 現在の状態
- 🔲 魔力パターンで「条件」と「分岐」をどう表現するかの具体的な仕組みを詰める
- 🔲 開発・習得のプロセス（主人公がいつ気づき、どう試行錯誤するか）を描く
- 🔲 他の術式師がこれを見た時の反応（理解できるか・模倣できるか）

## 部品⑥：魔石サーバー
**── サーバー・クラウドに相当 ──**

### 概要

上記①〜⑤を統合した最終形。
特定の場所（安全な地下室・隠し部屋など）に大量の魔石を集積し、
ネットワーク経由で遠隔からアクセスして使用できるようにする。

### できること（完成形）

| 機能 | 現代での対応 |
|------|------------|
| 遠隔地の映像を保存する | クラウドカメラ |
| 過去の保存映像を任意に呼び出す | 動画ストレージ |
| 複数の場所からネットワーク経由でアクセス | リモートアクセス |
| 魔法プログラムを動かし続ける | サーバー処理 |
| 膨大な情報を蓄積・参照する | データベース |

### 現在の状態
- 🔲 物理的な場所の設定（どこに置くか・誰が知っているか）
- 🔲 魔力の供給方法（常時稼働のためのエネルギー源）
- 🔲 セキュリティ（敵に発見・破壊された場合のリスク）

## 開発の順番（ロードマップ草案）

物語の進行に合わせて段階的に開発される想定。

```
STEP 1: 念写魔法の習得
　→ 「見たものを転写できる」という基礎能力を得る

STEP 2: 魔石への記憶保存
　→ 「転写した映像を魔石に保存・呼び出す」を発明

STEP 3: 魔法プログラミングの発見
　→ 術式に条件分岐を組み込む概念を発明。他の術式師が驚く

STEP 4: 魔石ネットワークの構築
　→ 中継魔石を各地に設置し通信インフラを作る

STEP 5: 遠隔視覚魔法の実用化
　→ 離れた場所の映像をリアルタイムで取得できるようになる

STEP 6: 魔石サーバーの完成
　→ 全部品を統合。「魔法のコンピュータ」が完成する
```

## この技術体系の世界的意義

完成すれば、この世界の情報・軍事・政治に革命をもたらす。

- **情報収集：** 敵国の動向をリアルタイムで監視できる
- **通信：** 伝令不要の即時遠距離通信（現状は念話使いが必要）
- **記録：** 文書・証拠・知識を完全な形で永久保存できる
- **危険性：** 誰かに技術が奪われると悪用のリスクが非常に大きい
